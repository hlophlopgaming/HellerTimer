# AGENTS.md — HellerTimer

Нативный клон Pomatez на Rust + Slint. Главная ценность проекта — **тот же вид и функции, что у Pomatez, но в разы меньше памяти и CPU**. Любое решение, которое ухудшает потребление ресурсов, требует обоснования в комментарии.

Полное задание и спецификация — в `PLAN.md`. Этот файл — правила работы с репозиторием.

---

## Рабочий процесс агента

- **Не открывать PR и не ждать CI.** Коммитить прямо в рабочую ветку.
- Самопроверка — только быстрые команды (см. ниже). Долгие сборки пакетов, Android и релизные workflow не запускать: их проверяет CI после пуша.
- Если задача неоднозначна — принять разумное решение, оставить `// TODO(decide): …` с вариантами и идти дальше, не останавливаться.
- Сверка с оригиналом: исходники Pomatez (`https://github.com/zidoro/pomatez`) клонировать во временную папку вне репозитория. Не копировать их в репозиторий целиком — только нужные ассеты в `assets/` с записью в `THIRD_PARTY.md`.
- Отличие от Pomatez в поведении помечать `// parity: <как в оригинале и почему иначе>`.
- Перед использованием API Slint сверяться с docs.slint.dev для версии из `Cargo.lock`: имена фич и winit-аксессоров меняются между версиями.

## Команды

```sh
cargo check --workspace                                   # основная проверка
cargo clippy --workspace -- -D warnings                   # должно быть чисто
cargo test -p heller-core                                 # быстрые юнит-тесты ядра
cargo check -p heller-web --target wasm32-unknown-unknown # если таргет установлен
cargo check -p heller-android --target aarch64-linux-android  # если таргет установлен
cargo run -p heller-desktop -- --start                    # локальный запуск
python bench/bench.py --help                              # бенчмарк против Pomatez
```

## Структура

```
crates/heller-core/     чистая логика: FSM таймера, конфиг, задачи. Без IO, без slint.
crates/heller-ui/       ui/*.slint + Rust-склейка, тема, i18n, трейт Platform
crates/heller-desktop/  Windows/macOS/Linux: трей, хоткеи, мини-окно, автозапуск
crates/heller-web/      wasm-точка входа
crates/heller-android/  cdylib + android/ (Gradle, Java-прослойка)
assets/                 шрифты, иконки, звуки, голос
bench/                  замеры против Pomatez
site/                   GitHub Pages
packaging/              flatpak, .desktop, Info.plist
xtask/                  вспомогательные задачи сборки
```

Направление зависимостей: `core ← ui ← {desktop, web, android}`. `heller-core` не зависит ни от чего платформенного; `heller-ui` знает о платформе только через трейт `Platform`.

## Правила кода

### Rust
- Edition 2021+, `rustfmt` по умолчанию.
- Нет `unwrap()`/`expect()` на путях IO, сети, платформы и парсинга пользовательских данных. Ошибки — в лог (`log`), приложение продолжает работать с дефолтами. В тестах и для заведомо инвариантных вещей — можно.
- Без `tokio` и любых async-рантаймов.
- Новые зависимости — только с `default-features = false` и минимальным набором фич. Не добавлять тяжёлые крейты (`image`, `reqwest`, `skia`), если есть лёгкая альтернатива. Каждая новая зависимость — одна строка в описании коммита «зачем».
- Платформенный код — за `#[cfg(...)]` в `heller-desktop`/`heller-web`/`heller-android`, а не в `core` или `ui`. Неподдерживаемая функция = no-op-реализация + `Caps` с `false`, без паник.
- Время таймера — только дедлайны в `SystemTime`. Никаких счётчиков тиков и `sleep` в цикле.

### Производительность (обязательно)
- Таймер ведёт один single-shot `slint::Timer` до `core.next_wakeup()`. Интервальные таймеры запрещены.
- Перед `set_*` свойства Slint сравнивать со старым значением; не дёргать перерисовку зря.
- Секундный тик — только когда окно видно. В трее приложение просыпается лишь на события и смену процента прогресса.
- Аудио-устройство не держать открытым.
- Не аллоцировать в горячем пути (форматирование времени — в переиспользуемый буфер).
- Если правка может повлиять на память/CPU — прогнать соответствующий сценарий бенчмарка или оставить `// PERF: проверить в bench` в описании коммита.

### Slint
- Разметка — в `crates/heller-ui/ui/`, один компонент — один файл, имена `kebab-case.slint`.
- Цвета, размеры, радиусы, шрифты — только из `export global Theme` (`ui/theme.slint`). Никаких литералов цвета в компонентах.
- **Не использовать стили std-widgets** — свои виджеты из `ui/widgets/`, чтобы выглядело как Pomatez. Исключения: `AboutSlint`, при необходимости `ScrollView`.
- Все строки интерфейса — через `@tr("...")`; переводы в `crates/heller-ui/lang/{en,ru}.po`. Новая строка = запись в обоих файлах.
- Анимации — декларативные `animate`, короткие; плавность кольца — `animate progress` при обновлении раз в секунду, а не частый тик из Rust.
- Логика — в Rust, в `.slint` только отображение и простые биндинги.

### Ядро
- Любое изменение поведения таймера — с тестом на `FakeClock` в `crates/heller-core/tests/`.
- Формат сохраняемых данных меняется только с увеличением `version` и миграцией со старой версии.
